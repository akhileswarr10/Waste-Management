# Project Overview: Smart Waste Management System (WasteFlow)
We are developing a complete full-stack predictive waste management platform to replace inefficient fixed-route collection. The system utilizes machine learning to predict bin fill levels and overflow risks, coupled with a Greedy Route Optimizer that prioritizes critical bins while collecting "on-the-way" bins.

# System Architecture & Tech Stack
* **Backend:** Flask (Python) with Scikit-Learn, Pandas, NumPy, and Geopy / SciPy.
* **Frontend:** React with Tailwind CSS and React-Leaflet (OpenStreetMap integration).
* **Database & Auth:** Supabase (PostgreSQL with Row Level Security & GoTrue Auth).
* **ML Artifacts Available:** 
  - `random_forest_waste_model.pkl` (Regression - 100 Trees)
  - `random_forest_overflow_model.pkl` (Classifier - 300 Trees)
  - `preprocessor.pkl` & `overflow_preproc.pkl` (Scikit-Learn ColumnTransformers)
  - `overflow_threshold.txt` (Threshold: 0.6200)

# Core Functional Specifications

### 1. Telemetry Simulation & Time Engine
Since real IoT sensors are not connected, the backend must include a **Time-Step Simulation Engine**:
* **Database State:** Stores virtual clock time, active bins, and their historical fill records.
* **Advance Time Mechanism (`/api/simulation/advance`):**
  - Allows advancing time by **+6 Hours** or **+1 Day**.
  - Applies realistic, localized stochastic fill rates:
    - *Commercial/Market:* Fast fill ($5\% - 15\% / \text{hour}$).
    - *Residential:* Moderate fill ($2\% - 6\% / \text{hour}$).
    - *Industrial/Parks:* Slower fill ($1\% - 3\% / \text{hour}$).
    - Applies weekend multipliers and random spike events.
  - Automatically appends these synthetic readings to historical telemetry so the feature builder can construct past lag arrays (1h, 2h, 3h, 6h, 12h, 24h).

### 2. Machine Learning & Priority Engine
* **Feature Builder:** Generates the exact 52-column feature vector required by the ML preprocessors (telemetry, historical lags, rolling averages, cyclical time sin/cos, weather/zone metadata).
* **Model Inference:**
  - Regressor predicts `target_fill_level_6h_pct`.
  - Classifier outputs `overflowProbability` (flags risk if $\ge 0.62$ or predicted fill $\ge 95\%$).
* **Priority Formula:**
  $$\text{Priority Score} = 0.40 \times \text{PredFill} + 0.35 \times \text{OvfProb} + 0.15 \times \text{CurrFill} + 0.10 \times \text{GrowthScore}$$
* **Urgency Tiers:** EMERGENCY ($\ge 100\%$), CRITICAL ($\ge 90\%$), HIGH ($\ge 75\%$), MEDIUM ($\ge 50\%$), LOW ($< 50\%$).

### 3. Greedy Route Optimizer & "On-The-Way" Collection
* **Depot Starting Point:** Driver starts at a fixed depot coordinate.
* **Target Filter:** Identifies primary candidate bins where $\text{Current Fill} \ge 80\%$ OR priority tier is HIGH/CRITICAL/EMERGENCY.
* **Greedy Path Construction:** Selects the nearest primary target iteratively using Euclidean/Haversine distance.
* **On-the-Way Corridor Collection:** 
  - For each leg from bin $A$ to bin $B$, check all non-target bins that have $\text{Current Fill} \ge 50\%$.
  - If a bin lies within a cross-track corridor/buffer distance (e.g., within 300 meters of the direct path vector between $A$ and $B$), insert it into the route sequence before reaching $B$.
* **Metrics:** Output total route distance, estimated drive duration, and calculated fuel savings compared to a fixed static route.

### 4. Role-Based Interfaces
* **Admin Dashboard:**
  - Interactive map displaying all bins color-coded by fill/urgency status.
  - "Simulation Control Panel" (Buttons to advance +6h, +1 day, or reset).
  - High-level KPIs: Total Bins, Bins at Risk, Average Fill %, System-wide Prediction MAE.
  - Historical collection logs table.
* **Driver Dashboard:**
  - Clean, mobile-first view showing the optimized route mapped out with numbered stops.
  - Sequential task list with ETA and bin details.
  - "Mark as Collected" button: Clicking this logs the pickup, resets the bin fill level to $0\%$ in Supabase, and dynamically refreshes the remaining route.
